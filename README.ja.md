# Cognis 外部モジュールテンプレート

[English](README.en.md) · [Deutsch](README.de.md) · [Bahasa Indonesia](README.id.md) · **日本語**

新しい外部 Cognis モジュールは、このリポジトリから作成します。導入可能なサンプルで UI、API、データベース、CLI、機能、フロー、翻訳、ライフサイクル検証、パッケージ完全性を示します。識別情報とサンプル内容を置き換え、開発標準と検証を保持してください。

## はじめに

```sh
npm install
npm test
npm run check:manifest
```

このリポジトリを Cognis モジュールソースとしてインストールし、権限を確認して有効化した後、`/showcase` を開くか `cognisctl modules:module-template:list` を実行します。

## アーキテクチャマップ

| パス            | 責務                                                                                   | 重要なポイント                                                     |
| --------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `manifest.json` | ID、互換性、ケイパビリティ、エントリーポイント、ストアメタデータ、固定ファイルハッシュ | UUID は依存関係、ID は人が読める名前                               |
| `bootstrap.js`  | ホストとの唯一の統合ポイント                                                           | `ctx` 経由で登録し、Cognis 内部をインポートしない                  |
| `routes.json`   | ページアクセスの事前宣言                                                               | ホストは有効化前に保護ルートを検証する                             |
| `api/index.js`  | 認証済み HTTP 境界とオーケストレーション                                               | 入力を検証し、永続化を委譲する                                     |
| `api/store.js`  | 移植可能なデータベースエグゼキューターコマンドとスキーマ                               | モジュールをデータベースドライバーに結合しない                     |
| `api/ui.js`     | 静的アセット、SPA ルート、ナビゲーション                                               | ホスト登録により無効化・アンインストール時の後処理範囲が限定される |
| `ui/`           | ブラウザーエントリーポイント、スタイル、4 言語のバンドル                               | `ui.stringsBaseUrl` を設定し、ホストのルートとトーストを使う       |
| `cli/index.js`  | `cognisctl` 拡張                                                                       | CLI は公開 API を呼び出し、迂回しない                              |
| `docs/`         | コントリビューター向け詳細資料                                                         | 契約と安全な拡張パターンを説明する                                 |
| `scripts/`      | パッケージ整合性チェック                                                               | 配布される全ファイルに SHA-256 ダイジェストを付ける                |

## ライフサイクルと境界

1. Cognis は `manifest.json`、コンポーネント依存関係、必要なケイパビリティ、ルート、ファイルダイジェストを検証します。
2. 有効化すると `bootstrapModule(ctx)` が呼ばれます。モジュールは UI/API コントリビューションを登録し、ケイパビリティを公開してフローを拡張します。
3. API ハンドラーは認証と検証を行います。ストアは `db:executor` を通じてスキーマと永続化を管理します。
4. UI と CLI は同じ HTTP API を使用します。他のコンポーネントは `ctx` 経由で `module-template:listItems` を利用できます。
5. スコープ付き登録は無効化時に削除されます。スコープ付き登録の外でタイマー、リスナー、ソケットなどを作成する場合は、明示的な disposer を追加して返してください。
6. アンインストール時は `uninstallModule(ctx, { deleteContent })` が呼ばれます。管理者がコンテンツ削除を要求した場合に限り、テンプレートはデータベース行を削除します。

コンポーネント間の振る舞いは **ケイパビリティ**（呼び出し可能な契約）または **フロー**（順序付き拡張ステージ）に置きます。Cognis、ゲートウェイ、兄弟モジュールのソースツリーへ直接アクセスしないでください。`requires` の必須コンポーネント参照には UUID を使い、実行時契約は `requiresCapabilities` に置きます。

## このテンプレートをフォークする

1. 安定した読みやすい ID を選び、新しい UUID を一度だけ生成します。公開するフォークでこのテンプレートの UUID を再利用しないでください。
2. パッケージ、コマンド、API/静的パス、DB テーブル接頭辞、ローカライズ名前空間、フロー拡張 ID、ケイパビリティキーを変更します。
3. パブリッシャー、リポジトリ、サポートのメタデータとアートワークを置き換えます。
4. manifest、package、lockfile のバージョンを一致させ、manifest の `ui.stringsBaseUrl` にモジュール所有の言語バンドルのベース URL を設定します。
5. 本当に必要なケイパビリティだけを追加し、ルートアクセスを最小権限に保ちます。
6. 最後に `npm run manifest:hashes` を実行し、その後 `npm run check` と `git diff --check` を実行します。

本番モジュールを実装する前に [`docs/index.ja.md`](docs/index.ja.md) を参照してください。同等のドイツ語、英語、インドネシア語版も同じ場所にあります。

## コントリビューター向け品質チェック

このテンプレートには Jitsi Meet モジュールと同じ自動ガードレールが含まれています。Prettier、可読性制限、外部モジュール構造チェック、ドキュメントテンプレートの整合性、曖昧な名前のチェックを行います。

```sh
npm install
npm run lint
npm test
npm run check:manifest
git diff --check
```

新しい契約ドキュメントには `.github/DOCUMENTATION_TEMPLATE.<language>.md` のローカライズ済みテンプレートを利用できます。4 言語版の構造を常に同期してください。
