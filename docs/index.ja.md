# 外部モジュールテンプレート

新しい外部 Cognis モジュールは、このリポジトリから作成します。導入可能なサンプルで UI、API、データベース、CLI、機能、フロー、翻訳、ライフサイクル検証、パッケージ完全性を示します。識別情報とサンプル内容を置き換え、開発標準と検証を保持してください。

## 使用例

- モジュールを有効化した後に `/showcase` を開き、ローカライズ済みの Page Composer UI を使用します。
- `cognisctl modules:module-template:list` を実行し、CLI から同じ認証済み API を使用します。
- モジュール内部をインポートせず、`ctx` を通して `module-template:listItems` を解決します。
- 名前付きで削除可能なステージから `module-template:listItems` フローを拡張します。
- モジュールを無効化して再度有効化し、スコープ付き登録の再現性を確認します。

## 技術仕様

以下は、Core のランタイム契約と隣接する Cognis モジュールで実証されたパターンをまとめた規則です。

### リポジトリとマニフェストの契約

- 1 つのリポジトリは 1 つのモジュールだけを提供します。`manifest.json`、`package.json`、`routes.json`、`bootstrap.js` はルートに維持します。
- UUID は永久に保持し、必須コンポーネントには UUID を使用します。マニフェスト、パッケージ、ロックファイルのバージョンを同期します。
- 正確なリポジトリ相対のエントリポイントとアセットを宣言します。`routes.json` は配列、`package.json` は ES module パッケージのままにします。
- `ui.stringsBaseUrl` を設定し、小文字の単語をピリオドで区切ったロケールキーを使い、ドイツ語、英語、インドネシア語、日本語のキーを一致させます。
- 必要なルート、Capability、依存関係、権限だけを宣言します。最後に `manifest.files` を再生成します。マニフェスト自身、`docs/changelog/`、任意のルート互換エイリアス `README.md`、すべてのシンボリックリンクおよびその他の非通常エントリを除外します。ローカライズ済み README は通常のパッケージファイルとして維持します。

### 分離とライフサイクル

- `bootstrap.js` はスコープ付き `ctx` を介してホスト統合のみを調整し、機能実装や Cognis 内部のインポートを含めません。
- Capability は中立的な契約です。非特権モジュールは、提供する Capability ID とフロー ID の先頭にマニフェスト ID を付けます。コロン区切りの各セグメントには camelCase を使い、任意コンポーネントは Capability で検出します。
- 意味のあるオーケストレーションには名前付きフローと安定した削除可能なステージを使います。ルートハンドラーは検証と調整を行い、Capability がプロバイダー固有の処理を実行します。
- Disposer または `teardownModule` は、スコープ外のタイマー、リスナー、ソケット、スクリプトを削除します。`uninstallModule(ctx, { deleteContent })` は明示的に削除を要求されない限り外部コンテンツを保持します。
- インストール、有効化–無効化–再有効化、アンインストールを確認します。ルート、アセット登録、UI コントリビューション、Capability、フックをサイクル間に残しません。

### UI とホストの所有権

- ホストの Page Composer でページを構成し、ホストルーターで移動します。ナビゲーションにはリンク、操作にはボタンを使います。
- モジュールは mount root 内の自身が所有する子孫だけをスタイルします。シェル、`document.body`、`document.head`、ホスト所有クラスを変更しません。
- 共通 UI 部品とスタイルは `ui:reuse` から取得します。ランタイムスクリプトは `ui:resourceLoader` で読み込み、ハンドルを破棄します。
- Toast、エラー／判断 Popup、時刻、Theme、Font、Avatar、Focus はホスト契約を使用します。ブラウザーダイアログ、再読み込み移動、任意の状態ノード、CSS コメント、コピーしたホスト CSS は使用しません。
- 表示テキストとアクセシビリティ文言を 4 つの XML バンドルでローカライズします。絵文字やプラットフォーム依存グリフよりテーマ対応 SVG を優先します。

### API、データ、設定

- 境界で入力を検証・正規化し、ビジネスロジックより前に認証・認可します。内部詳細を含まない安定したエラーを返します。
- 永続化は `ctx` の Executor とモジュール所有 Store の背後に置きます。クエリをパラメーター化し、スキーマオブジェクトに名前空間を付け、具体的な Driver はインポートしません。
- 呼び出し側が指定しない結果上限を作りません。明示された上限は暗黙に切り詰めず検証します。
- 管理者設定には第 2 の設定画面ではなく、マニフェストの `ui.preferences` とモジュール設定 API を使用します。無効化／再起動後も設定を保持し、保存済み Password は返しません。
- ユーザー固有の Secret はホスト Keyring に保存します。ID と Secret の生成には `Math.random()` ではなく Web Crypto または Node Crypto を使います。
- 状態変更は `info`、捕捉した失敗は安全な構造化コンテキスト付きの `error`、未捕捉エラーは fatal として記録します。意図的なフォールバックも必ず記録します。

### 構造と品質

- Server、Browser、CLI、Documentation、Data、Tooling、Artwork はそれぞれ `api/`、`ui/`、`cli/`、`docs/`、`data/`、`scripts/` または `tooling/`、`assets/` に置きます。
- レイヤー内で本当に横断再利用できるコードは `reuse/` に置き、機能固有コードは所有機能の近くに保ちます。`shared`、`utils`、`helpers`、`common` ディレクトリは作りません。
- ファイルは凝集的かつ 1000 行以内にします。説明的な名前、読みやすい制御フロー、有用な制約コメントを優先し、廃止契約の互換 Shim は追加しません。
- テストはローカルの `ctx` Fake で単独実行し、公開 API、Capability、フロー、認可、ローカライズ、ライフサイクル、マニフェスト整合性を対象にします。

### リリースチェックリスト

1. 依存 UUID、必須 Capability、ルートアクセス、メタデータ、翻訳、Artwork、Secret の扱いを確認します。
2. 契約、コード、スキーマ、API の変更では、マニフェスト、パッケージ、ロックファイルのバージョンを同期します。
3. `npm install`、`npm run lint`、`npm test` を実行します。
4. 最後の配布ファイル編集後に `npm run manifest:hashes`、続いて `npm run check:manifest` と `git diff --check` を実行します。
5. テンプレート以外のモジュールでは、4 言語の `docs/changelog/<branch>.<lang>.md` を追加し、Changelog を Digest 対象にせず Commit 出所を完成させます。

新しい外部モジュールは必ずこのテンプレートから始めます。製品 UUID を一度だけ生成し、サンプルのメタデータと名前空間を置き換え、AGENTS.md と検証ツールを保持します。ドメインルートは `api/routes/<domain>/`、スタイルは `ui/styles/`、マークアップは `ui/templates/`、リリース文書は `docs/changelog/` に配置します。API の読み書きは登録段階を実行し、ブラウザーはページコンポーザーと限定されたナビゲーションを利用します。
